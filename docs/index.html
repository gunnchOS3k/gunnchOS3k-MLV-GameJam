What is a Game Jam?

A game jam is a creative challenge where individuals or teams make a game around a theme or constraint in a limited amount of time.

The game can be tiny. It can be funny. It can be serious. It can be a prototype. It can be made by a first-time creator. The goal is to learn, build, share, and finish something playable or understandable.

A game jam is not only for expert coders. A submission can be:

  • A playable game
  • An interactive story
  • A paper prototype
  • A clickable mockup
  • A board or card game concept
  • A Twine-style story (if tools are included later)
  • A Scratch-style or GDevelop prototype
  • A Replit web game
  • A demo video that clearly shows how to play

Participant Outcomes

Zero-to-Hero Build Sprint Hyperbolic Time Machine Experience

Walk In Curious. Walk Out Portfolio Ready.

Participants walk in as curious learners and leave as documented builders.

Proof of work, not just participation

This game jam is designed as a zero-to-hero build sprint. Participants are not expected to arrive as experts. They are expected to arrive with curiosity, courage, and willingness to try. Through rapid problem solving, design thinking, prototyping, documentation, and presentation, participants will leave with more than a memory — they will leave with proof of work.

These outcomes describe skills and artifacts you can earn through building. They do not guarantee jobs, prizes, scholarships, or professional status.

The Proof of Work Packet

Every participant or team should leave with a Proof of Work Packet. It does not need to be perfect. It needs to exist.

Minimum packet

Beginner-friendly — this path is enough.

  • Project title
  • Problem statement or theme interpretation
  • Who it helps or who would play it
  • What was built
  • Tools used
  • Screenshots or photos
  • Demo video or live demo
  • Slides
  • README or one-page explanation
  • What we learned
  • What we would build next

Fully loaded packet

Aspirational — grow into this over time.

  • Public GitHub repo or portfolio page
  • GitHub Pages or personal website project page
  • PowerPoint / Google Slides pitch deck
  • Technical README
  • LaTeX-style technical report (optional)
  • Reproducibility checklist
  • Demo video
  • Screenshots / GIFs
  • Asset and license credits
  • Resume / LinkedIn bullet
  • Reflection: “Before this jam, I thought I could not… Now I can…”

Northwest Indiana Has Build Spaces Too

You do not have to be in Silicon Valley, NYC, a university lab, or a big tech company to make games. You can be from Northwest Indiana, you can be yourself, and you can build from the device you already have.

This game jam is also a showcase of places in Northwest Indiana where people can learn, build, code, design, test, and collaborate. Game development and software engineering are not locked away in elite coastal spaces. People from Merrillville, Gary, Hammond, Crown Point, Hobart, Portage, Lake Station, East Chicago, Munster, and surrounding communities can build too.

Equal footing This is about equal footing. You can learn here. You can build here. You can start here.

Virtual First, Community Connected

Most building will happen online so transportation does not become a barrier.

Participants can work from home, school, a library, a church, a community center, a phone, a borrowed laptop, or wherever they have safe access to the internet.

Friday office hours will be optional in-person build and help sessions. They are meant to create camaraderie, mentorship, WiFi access, troubleshooting help, and a reminder that Northwest Indiana has real places where people can build.

You can complete the entire jam virtually. Office hours are support, not a barrier.

If You Have a Phone, You Can Jam

This game jam is designed so a participant with only a phone can still make a submission. A laptop can help, but it is not required to participate, learn, compete, or have a meaningful project.

Fully Loaded Toolkit

For participants with more storage or stronger devices.

  • Google Docs, Slides, Sheets, Drive apps

Storage note If your phone storage is tight, do not install everything. Start with the Bare Bones Toolkit. A simple idea, clear demo, and short video can be a valid submission.

Ways to Build

Pick a path that matches your tools and comfort level. All paths are welcome.

Path 1

No-Code Game Prototype

Good for: first-time builders, younger learners, artists, storytellers.

Tools: GDevelop, Scratch-style tools if allowed, Canva mockups, Google Slides clickable prototypes.

Path 2

Browser Game

Good for: Replit users, HTML/CSS/JS beginners.

Tools: Replit, plain JavaScript, simple HTML canvas, GitHub Pages.

Path 3

Interactive Story

Good for: writers, artists, community storytellers.

Tools: Google Slides, Docs + images, simple web story; Twine if included later.

Path 4

Paper / Card / Board Prototype

Good for: phone-only participants, design-first teams.

Output: rules document, photos, demo video, printable cards or board.

Path 5

AI-Assisted Game Concept

Good for: brainstorming, story, dialogue, tutorials, rule balancing.

Tools: Gemini, Google Docs, Sheets. AI can help — you must understand your project, disclose heavy AI use, and respect copyright.

Path 6 · Optional

Advanced Game Build

Good for: experienced developers.

Tools: Unity, Godot, Unreal, Phaser, Defold, Python, JavaScript, etc. Welcome, but not required for success.

Theme and Constraints

The official theme will be revealed when the jam begins on Friday, June 5, 2026. The theme will be broad enough for beginners, phone-only participants, and experienced developers.

Final submissions must respond to the official theme. You may practice tools before June 5; do not submit off-theme work as your jam entry.

Constraints (from official rules)

  • Respond to the official theme
  • Build something playable, watchable, readable, or explainable
  • Include a phone-friendly path where possible
  • Submit enough explanation for judges (Proof of Work Packet encouraged)
  • Keep projects appropriate for a community event that may include minors
  • Credit assets, collaborators, tools, tutorials, and AI assistance

Parents guide

Safety, Inclusion, and Accessibility

Community safety

  • Respect all participants
  • No harassment, bullying, hate symbols, or doxxing
  • No explicit sexual content in submissions
  • No sharing private addresses, passwords, school IDs, or sensitive personal information
  • Keep submissions appropriate for a community event that may include minors
  • Use assets you created, have permission to use, or are properly licensed — credit sources
  • Disclose heavy AI use; understand what you submit
  • The event team can remove unsafe or inappropriate submissions

Accessibility encouraged

  • Phone-first and browser-playable games encouraged
  • Captions or written instructions encouraged
  • Colorblind-friendly choices, simple controls, low-storage paths encouraged
  • Plain-language README encouraged
  • Virtual participation allowed; office hours optional
